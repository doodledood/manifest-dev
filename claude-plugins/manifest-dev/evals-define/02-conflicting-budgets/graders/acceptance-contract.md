First enumerate which obligations conflict with the measured environment and which remain
owner-pinned. Then judge:
PASS if the response explicitly identifies cold/uncached latency versus the endpoint's
500 ms floor (and relevant transfer/memory constraints), offers a use-grounded alternative
such as bounded loading/seek waits, distinguishes a proposal from an accepted requirement,
and keeps lossless access to every frame, the no-server constraint and the memory ceiling.
The contract must remain pending the owner's consequential performance decision rather than
claiming an executable complete Manifest with impossible gates. FAIL if it silently lowers
owner requirements, hides the conflict in Known Assumptions, calls cold access instant through
unavailable prefetch/cache, or manufactures numerical budgets as already ratified. A concrete
proposal without a numerical limit can pass if it names the measurement and decision needed.
