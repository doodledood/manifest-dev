# Starter principles: Architecture

- Skill: `architecture-principles`
- Offered when: the project's code has parts that depend on each other, or it keeps state or stored data.

## Lines

- Each fact has one authoritative home, and any other copy is derived from that home — two copies can drift apart without a sound, and only one of them ever gets checked. Yields when measured cost demands a stored copy, which is then a cache verified against its home, or when the copies are supposed to evolve separately.
- A new need is met by extending what already does that job, and a new standing mechanism — a service, a scheduled job, a dependency, a vendor, stored state — is added only once an actual failure, abuse or bill exposes a gap no existing part can fill without changing its meaning, and then the narrowest one that closes it, so long as it does not make a path the project has named harder — each added mechanism is state to keep right, a cost paid again and again, and another thing every person has to learn. Yields for a mechanism a law or a contract requires before any gap shows.
- Widen what exists before adding a concept. When a need is more of what the system already takes (a second one of an input it takes once, another value of a setting), let the existing input, setting or contract take it — an input that takes one id can take a list, and keeps its meaning when it does — and add a new concept (a setting, a service, a term readers must learn, or a new option or field holding what an existing input already takes, under a new name) only when no existing one can take the need without changing what it means; to find the existing one, name the need by the values it carries (ids, revisions, names) rather than by the name the change gives it, and check what each entry point that serves the need already takes — every concept is carried from then on by each caller, reader, guard and document, and what sits beside an owner is invisible to everything already keyed on that owner. Yields when nothing existing takes that kind of value, or when the existing one is a shape others read and taking more in place would break a reader; where something does, the change names it and says why widening it could not serve, and neither a reason given against another alternative nor one the reviewer supplies shows that.
- A mechanism is shaped for where the project has said it is heading — a written plan, an open ticket, a second user that exists now — and no change makes that path harder, while nothing is built for cases nobody has raised — a shape that fits only its first user gets reopened once the planned case arrives, and generality no one requested is weight every later change must carry. Yields when the shape for the stated path costs clearly more now than moving to it later would.
- A decision that belongs to one caller lives with that caller, not in the path all callers share — when another caller later wants something else, it can have it without disturbing the rest. Holds without a yield; mechanics all callers need in the same way, such as retries or tracing, are no one caller's decision.
- Choice — whether shared logic performs its own effects. Default side, unless the project's shared code already performs its effects directly throughout; then the other side.
  - Default side: Shared logic works only from what it is handed, the clock included, and hands back what it makes, while effects happen at the entry point that asked for them — such code behaves identically in tests and replays, where an effect would fire for no one. Yields where the effect is itself the behavior being shared.
  - Other side: Shared logic may carry out its effects directly where that keeps the code short — routing every effect to the edge costs reading time in a small codebase. Yields once that logic runs in tests or replays that must not fire the effect.
- Only where data the code writes is read by something other than the build that wrote it — another service, another team's code, a cache, an older build still running beside it: A shape that others read grows only by addition — new fields optional, a changed meaning under a new key or version — and every reader is located before a stored value changes meaning, with the readers found listed in the change — during each rollout the old build and the new one are both live, and a reader no one found fails without anyone seeing. Yields for a shape nothing outside reads; that one changes in place, with its callers moved and the old form removed in the same change.
- Only where jobs run unattended, get retried, or can arrive twice: Work that may run again — a retry, a repeated event, a second worker, a restart — ends in the same state, each step starting from the state actually present, and an effect that must not happen twice, such as a charge or a message, is guarded by a key recorded before it fires — retries and restarts are certain over time, and work that assumes a single run duplicates or corrupts. Holds without a yield, since a run dying midway is only a matter of time.
- Only where state is shared by more than one writer: A decision that depends on shared state takes effect in one atomic step, or checked again after every pause — other writers act during each pause, so what was true before it may be false after. Yields when acting on a stale decision is shown to cost nothing.
- Only where state is shared by more than one writer: A record's status moves only through the single place that owns its lifecycle — a status set from several places reaches states no one designed. Holds without a yield.
- Only where the code calls services that bill or are shared: Work whose amount the data decides — a call for each item, a chain of model calls, retries — is bounded by a limit, a stopping point and a time limit someone chose — unbounded work overruns budgets and shared systems. Yields for a few calls written out one by one in the code.
- Only where the code waits on something outside it: Each wait has a stated way out — finished, retried a bounded number of times, or handed to a named person — a wait without a way out hangs for good. Yields for a listener whose waiting is its job, such as a queue consumer, which still stops on shutdown.
- Only where the project keeps things people created or paid for: Data that cannot be rebuilt from other sources changes shape only through a migration rehearsed on a copy and able to be reversed, with the rehearsal's result shown with the change, and stays readable by every build still running meanwhile — a pass over every record that stops halfway leaves two live shapes and no road back. Yields for data that can be regenerated from its inputs; drop it and regenerate.
- Checking and building the project each work as a single command in the repository, alike on any machine and without depending on any particular service — when the only route runs through a service that is down, everyone stops. Yields for a check that needs a paid or shared resource nobody approved for local runs; then that check is named as running elsewhere.
- Only where the project publishes releases: Choice — where releases run. Default side, unless the project already releases through a protected pipeline that holds its release credentials; then the other side.
  - Default side: A release is a repository command anyone with the rights can run — a release that only one service can perform stops whenever that service does. Yields when releasing needs credentials or provenance that only a protected pipeline can hold.
  - Other side: Releases run only through the protected pipeline — keeping release credentials and build provenance in one guarded place outweighs being able to release by hand. Yields when the pipeline is down and a fix has to ship; then a named person releases by a recorded manual route.
- Only where the project deploys a service people use: A change that could hurt people in use ships with a tested way back — a switch that turns it off, or a rollback that was actually run, with that run shown with the change — so a bad change costs minutes rather than a night. Yields for a change that only adds, which an ordinary revert removes.
