# Starter principles: Agent behavior

- Skill: `agent-principles`
- Offered when: the project writes prompts or skills, or builds a feature on a model.

## Lines

- When a model's output is wrong, the cause is placed first — data it lacked, a safeguard missing from code, knowledge it was handed, or its instructions — and the repair goes to that layer, which the change names — words added to cover a wiring fault are paid on every run and cure nothing. Holds without a yield, since the layer named can be the instructions.
- When a miss traces to an instruction, that instruction is rewritten or removed where it stands, rather than a second one added beside it or the first one repeated louder — two instructions about one moment compete, and emphasis moves little. Yields for wording an evaluation measured: the edit is made, and that measurement is marked stale until it runs again.
- An instruction is written for the class of cases it governs — the condition, what is owed under it, and what to weigh where a call is needed — rather than around the incident that prompted it — wording fitted to one case fails on its neighbor. Yields where runs were seen to need the literal steps, or where law or a contract fixes the wording.
- A new instruction is read inside everything the model receives, settled against each instruction it overlaps, and made to depend only on facts and tools that run really has — when two instructions disagree the model picks one, and a distinction its input cannot show cannot be acted on. Yields for an intended override, which names the instruction it replaces.
- Every example a prompt gives obeys every instruction around it — models imitate examples, so one example that bends a rule trains the model to bend it. Holds without a yield.
- A prompt states what it means when an input is empty or absent, and puts early any fact whose absence the model would take as a safe no — a model reads silence as information, and then makes something up or declines. Yields when the data cannot back such a statement every time; then say less rather than claim more.
- A change to a model's instructions, inputs or permitted actions is tried in a real run, reading what it received, decided and produced on one case the change has to catch and one where it has to stay quiet, and that run is shown with the change — reading the words cannot show what a run will do with them. Yields when the change leaves what the model receives and returns untouched.
- Judging meaning is left to the model under its instructions, and anything that has to be true on every run is enforced in code — phrase matching misreads meaning, and no prompt guarantees anything. Yields where the case needs a check that is deterministic, auditable or fast, and for a cheap code filter tuned to over-trigger ahead of the model's fuller judgment.
- Only where a model's output reaches the people who use the product: What a model is shown is chosen one field at a time, keeping out whatever it neither needs nor may repeat — a model passes on what it reads. Yields where the model has to know something it must never pass on; then an instruction and a code check both guard that fact.
- Only where a model takes actions: A model holds only the tools and permissions its task needs, and any action that cannot be undone passes a gate in code rather than an instruction — whatever a model holds, it will in time use. Yields inside a sandbox whose effects are discarded.
- When the model behind a feature changes, the checks its prompts passed run again before that change ships — a prompt tuned on one model can behave differently on the next. Yields when no such check exists yet; then the change states that the prompts are unverified on the new model.
