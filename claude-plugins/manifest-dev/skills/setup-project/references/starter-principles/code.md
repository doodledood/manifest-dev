# Starter principles: Code

- Skill: `code-principles`
- Offered when: the project holds code.

## Lines

- A defect is repaired where every caller passes, and every other site with the same fault is found and repaired with it — a patch at the one site that was noticed leaves its siblings broken and lets the next person make the same mistake. Yields when the fix is urgent or the sweep is large: the instance lands first, and the class follows in the next change, which the first one names.
- The result a change owes decides what it touches, and of the routes to that result the one that alters least is taken; a change made smaller by delivering less is not smaller, only unfinished — a small change is cheap to review, to roll back and to think through, so long as nothing owed is missing from it. Yields when the least-change route makes a change the project has already named harder to make.
- Whatever a change leaves unused — code, flags, settings, tests, mentions — goes in that same change — a leftover tells later readers that something still works which no longer does, and every kept part must still be read and kept accurate. Yields when someone asks for a part to stay, or while outside callers still depend on it.
- When the code a change must build on resists it, a separate step reshapes that code first without changing its behavior, held by tests, and the change follows — work layered on a tangle inherits the tangle, and a step that changes no behavior is easy to review. Yields when that code is not expected to change again.
- A module offers a small interface over a substantial job, and no layer exists only to hand calls on — callers have little to learn and much to gain, and a later change touches one place instead of several. Yields for adapters and for seams tests need, which may be thin on purpose.
- Data arriving from outside — a request, a stored row, a file, a model's reply, what a person types — is checked and converted to the program's own form once, at the point it enters, and only that converted form travels inside — a value used before it is checked fails wherever it is first touched, and checks spread through the code come to disagree. Yields for free text whose content is the point, which stays text.
- Data is shaped so that a state which must never occur cannot be expressed at all — each guard against an impossible state is one more place someone can forget. Yields when the language offers no way to express the limit; then one constructor enforces it.
- A failure or a gap is reported as what it is, where it happens, and never dressed up as success, an empty result, a zero, the closest category or a believable default — a swallowed failure passes on data nobody can trust, and an invented default sails through every later check. Yields where running in a reduced mode is explicitly wanted; then the code does so and leaves a signal that tells the reduced path from the normal one.
- Where the surrounding code already does a thing one way, a change does it that way too, unless the change replaces the old way everywhere — two ways of doing one thing double what each reader has to learn. Yields when the existing way is the defect the change removes.
- A rule that must hold is held by a check — a type, a required argument, a lint, a test whose failure says what to fix — rather than by a sentence someone must remember — a rule left to memory gets broken sooner or later, and quietly. Yields when the check would cost more to keep than the mistakes it would catch.
- A test drives behavior through the interface its callers use, and its expected values are written out rather than derived the way the code derives them — a test that still passes once the behavior is gone proves nothing. Yields for a unit that has no caller-facing interface yet, which is tested at its own edge.
- A bug fix comes with a test seen to fail on the code before the fix, and that failing run is shown with the change — the failing run is the evidence that the cause was understood. Yields when no automated test can reproduce the bug; then it is reproduced in a real run, and that run is shown.
- A check is never made to pass by removing, skipping or loosening it — a green result that hides a failure is worse than a red one. Yields when the check itself is wrong; then it changes, and the change says why.
