# Upgrading a project from v15: what v16 gives it

Offer the verification-tool update only to a project that keeps the harness. Compare the
project's copy with `../harness/verify.mts`, preserve its configured paths and local changes,
and apply the same behavior in its own language if it has a port. The update keeps one complete
summary per scenario after overlapping drives finish, with a clear remedy for a leftover
publishing hold. A project that verifies its own way gets none of this.

Record the newest surfaces version only after each applicable offer has an answer.
