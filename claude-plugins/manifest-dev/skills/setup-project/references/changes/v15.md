# Surfaces v15

- Setup offers principles skills: one project skill per high-signal area of the project's work —
  design, product, prompts, architecture or another — named `<area>-principles` and holding how the
  project's people want that area's work done, each line a principle with its reason and when it
  yields. An area is high signal when its history holds several corrections or review asks with a
  stated reason, when the context file already holds principles only that area's work needs, or,
  on a project with no history, when it does that kind of work and a shipped skill holds an
  opinionated base for it. Lines come only from what the project's people said, and only the
  person's yes writes one.
- Principles and Taste entries in the project context file that only one area's work needs are
  offered as moves into that area's skill, so every session no longer carries them.
- The project-surfaces section gains one pointer line per principles skill, saying when to load it
  and where it is, so an agent without manifest-dev finds it too.
- A project that keeps no principles skill gains nothing in its context file.
