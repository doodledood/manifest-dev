# Continuity and delivery

Extend the task model only with conditions that change the design. A static asset needs no invented state machine; an unfamiliar medium needs its own requirements rather than inherited web defaults.

## Stateful, shared or consequential work

Distinguish saved, unsaved, pending, failed and stale state where those can occur. Name what persists and when an action commits; exercise interruption, return, retry and recovery. Shared work also needs applicable permission and conflict paths. Offline writes are a product choice, not a default obligation.

Make consequential effects, recipients and disclosure clear before commitment. Preserve understandable correction, cancellation and exit. Increased activity or completion cannot offset unintended actions, lost work or misleading commitments. For AI experiences, distinguish a suggestion from a committed action and test a plausible wrong answer, changed request and recovery.

## Delivery changes what must be verified

| Delivery | Evidence an ordinary browser screenshot cannot supply |
|---|---|
| Projected presentation versus standalone reading deck | A talk deck supports a speaker and a room: its argument-bearing slides need readable claims and evidence, with pacing controlled by the speaker rather than audience-operated exploration. A reading deck carries enough explanation to work alone. Compose for that encounter; a 16:9 canvas alone does not make a page a presentation. Inspect the intended view and sequence. |
| Documents, PDF, EPUB, print or exported images | Final-file reading order, text, tables, links, cropping and required production properties in the intended host or output. A web preview is not the export. |
| Spreadsheet or workbook | Editable inputs versus formulas, units, errors and dependencies: change an input and inspect the result in the native file, including relevant keyboard/assistive navigation. |
| Audio, video, animation or synchronized media | Full playback, timing, endings and required captions, descriptions or transcripts. Inspect the alternatives; they serve different access needs. |
| Voice, conversation or command-line interfaces | Misunderstanding, interruption, correction, cancellation and exit; distinguish human-readable from machine-readable output where relevant. |
| Native, spatial, embodied or unfamiliar platforms | Target-specific input, orientation, interruption, comfort and safe exit on the actual device. Obtain current platform guidance—for Apple platforms, the applicable [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)—and name unavailable specialist verification. |

For multi-page journeys, test deep-link arrival, finding the right object, backtracking and handoffs as well as the happy path. For interactive or temporal work, test control, repetition and return; a still frame cannot verify what unfolds over time.

Record the host, format, input and states actually covered. Model role-play and screenshot critique are not audience research. Where required evidence is unavailable, report the gap rather than letting a convenient preview stand in for it.
