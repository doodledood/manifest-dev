# First-impression estimates

`appearance` consumes a supplied raster or feature JSON. Python 3 and Pillow decode images; supplied features need only Python's standard library. The caller chooses and records capture, viewport, crop and state. The frozen profile uses adjacent gradients, thresholded edge fractions, luminance entropy and colorfulness at independent 128/256/512 maximum-edge views. These are image properties, not gaze or feature congestion.

Four separate axes estimate average first impressions in the historical screenshot dataset: complexity, aesthetic appearance, craftsmanship and novelty. Complexity and novelty have no universally desirable direction. Craftsmanship means the impression named by that survey, not verified implementation quality. Outputs retain the original 1-7 training scale and remain unbounded; they are neither probabilities nor personal ratings. Feature distances are descriptive, not calibrated uncertainty.

The [human-rating dataset](https://doi.org/10.7910/DVN/XEYNYW) contains 1506 website screenshots from six collections. Models fit 565 images, selected variants on 184 images from a different collection, then evaluated once on 756 images from two reserved collections after exact-duplicate screening. Native-only rank correlations were .555 complexity, .445 appearance, .467 craftsmanship and .559 novelty. All four improved rank correlation versus a development-selected model using the earlier four 512px descriptors; absolute rating error improved less consistently. Source separation and pixel screening cannot guarantee independent brands/templates. Image-group bootstrap intervals omit systematic rater variation and are nominal, without multiplicity adjustment.

An independent study published 2024 rated full-page [banks](https://doi.org/10.7910/DVN/Z7KLIH), [shops](https://doi.org/10.7910/DVN/9FKSQI) and [universities](https://doi.org/10.7910/DVN/XOI0HI).420 images were selected by filename hash before analysis. Without refitting, native appearance estimates correlated .290 with full-page appearance ratings and .370 using the predeclared top900px crop. The crop showed no clear refinement gain versus the earlier four descriptors. Those ratings measure perceived ease/trust from appearance, not actual usability or trust. Whole-page downsizing can erase text; full-page and viewport inputs are different conditions.

Blur, deleted details or empty layouts can improve a number while harming meaning. An appearance estimate can misrank real human-rated screens, and accurate complexity prediction does not imply appeal. Former approved landing/explainer examples serve as development stress cases, not independent outcome labels. Use matched conditions and inspect the actual artifact before keeping a change. Prefer no estimate when purpose, content, style, motion or audience differs enough to make the comparison contrived.

Technical-condition prediction failed to improve reliably and worsened rating error; it is withheld. Search-duration models from [VSGUI10K](https://osf.io/hmg9b/) showed only modest gains mainly for image cues, with uncertain benefit for text cues and unverified task success; they remain research tools. Geometry, visibility and the other instruments report supplied facts. Their arithmetic checks do not establish general UX validity.

The [development harness](https://github.com/doodledood/manifest-dev/tree/main/scripts/design-evals) retains protocol, fitting and reporting methods. Any later tuning needs new unseen evaluation data; these datasets are now regression evidence. No experiment here establishes causal improvement from using the design skill or hill climbing its estimates.
