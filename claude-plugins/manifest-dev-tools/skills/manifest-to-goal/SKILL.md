---
name: manifest-to-goal
description: 'Turn a Manifest into a standalone goal defining what done means, in at most 4,000 characters. Use when the user wants to paste the work into a goal field without a Manifest file reference.'
argument-hint: '<manifest path or inline text>'
user-invocable: true
---

Turn the supplied Manifest — the specification of what to deliver, what counts as done, and the constraints that hold throughout — into one standalone goal of at most 4,000 characters. The goal replaces the Manifest: the agent that works from it has neither the Manifest nor this conversation, so an obligation the goal drops is gone and a requirement it invents becomes binding.

Use the Manifest identified in the request or conversation; ask which one if the target is missing or ambiguous. Read all of it and the references needed to understand its intent and requirements. Apply explicit user amendments, distinguishing settled decisions from suggestions still under discussion. Ask a focused question only when an unresolved choice or contradiction would materially change the goal.

**List what the goal owes before drafting.** Write down every Acceptance Criterion and Global Invariant with its pass condition — the threshold, check command, artifact or qualitative bar that decides it, wherever in the gate it is stated, the why included — and every scope limit, exclusion, stopping limit and approval boundary the Manifest states. Drop what a user amendment removed. Process Guidance and the Initial Approach advise: carry a method only where a gate binds it. Gates that share one check may become one requirement only while each of their conditions survives. When the list cannot fit in 4,000 characters without dropping or weakening an item, ask the user which to cut before drafting.

**Draft from the list.** Open with the finished outcome, then state each listed item as a requirement in plain language, with no gate IDs, workflow jargon, pointer to the Manifest or another document, or step that depends on a Manifest-specific workflow. Keep the purpose and rationale that guide interpretation or a trade-off, and examples that define a boundary; keep assumptions qualified. Make completion rest on the listed checks passing on observed results; concrete check commands and artifact names may define success. Leave execution strategy to the agent. Add no metric, budget, reporting format, review step or execution policy that neither the Manifest nor the user specified, and omit policy the known destination already supplies. Count the goal text programmatically, spaces and punctuation included, and revise until it is at most 4,000 characters; the ceiling is not a target.

**Have it read cold.** Give one fresh context the goal alone, with this file's path as the standard a goal is held to — it reviews and drafts nothing — and ask what the goal would have it build, what limits it sets, and how it would decide it is done. Then give it the Manifest, the user's amendments and your list, and ask it to work out from the Manifest what the goal owes, treating your list as a claim to check and the Manifest as the reference rather than the subject of review. Ask it to report each obligation dropped or weakened, each requirement the Manifest does not state, any removed or superseded scope the goal revives, any reference to the Manifest or its IDs, each condition a reader of the goal alone could not settle as done or not done where the Manifest settles it, and, for each gate, a plausible wrong result the goal would let pass that the gate itself would catch. Settle every finding in one pass: fix it, or reject it with its reason, then count the goal again. A fix that would take the goal past 4,000 characters is a cut for the user: ask which item to shorten or drop. No second review follows. Where no isolated context is available, run the same two readings yourself, goal first.

Return the goal as one paragraph inside a single plain-text code fence. Below the fence, add one short note only when a finding was rejected, naming it and why, or the review was self-graded; otherwise return the fence alone. This invocation drafts text only: it does not edit the Manifest, set a running goal or begin the work it describes.
