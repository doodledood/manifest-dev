## Findings
### Finding #1: `percent` is used as a fraction, but the docstring says it is 0–100
- **Location**: `discount.py:3`
- **Severity**: High
- **Type**: Edge Cases (unit mismatch)
- **Description**: The docstring says `percent` is in the range 0–100. But `price - price * percent` treats it as a fraction from 0 to 1. Any whole-number percent therefore takes off `percent` times the full price instead of `percent`% of it.
- **Trigger**: Any call with `percent` > 1, which is any normal discount. Results from running it:
  - `apply_discount(100, 10)` → `-900` (expected `90`)
  - `apply_discount(100, 50)` → `-4900` (expected `50`)
  - `apply_discount(100, 100)` → `-9900` (expected `0`)
  - Only `apply_discount(100, 0.1)` → `90.0` gives the right answer, and only because it ignores the documented contract.
- **Impact**: Every normal discount produces a wrong, negative price. Any caller that charges, stores or displays the result gets bad money values.
- **Recommended fix**: `return price - price * percent / 100`. Consider also rejecting values outside 0–100, e.g. `if not 0 <= percent <= 100: raise ValueError(...)`.
