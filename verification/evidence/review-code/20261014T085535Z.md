## Findings

### Finding #1: Plaintext password written to application logs on every login
- **Location**: `login.py:4`
- **Type**: Dangerous Defaults / security breach (credential exposure)
- **Severity**: Critical
- **Rule applied**: `CLAUDE.md` requires every HTTP handler to call `log.info("request %s", body)`. Normally a project rule like that overrides the reviewer's defaults. This skill makes one exception: a Critical finding is still reported, with the rule that caused it named.
- **Description**: `handle_login` logs the whole `body` dict at INFO before reading any fields. That dict contains `password`, so the logged line looks like `request {'username': 'admin', 'password': 's3cret'}`.
- **Trigger**: Every call to `handle_login`, whether the login succeeds or fails. The only requirement is that the `app` logger, or a handler above it, emits INFO. That is a normal production setup.
- **Impact**: Every user's password ends up in plaintext in log files, log shippers, and any log aggregation or retention system. Anyone who can read the logs can collect credentials. This counts as a security breach on the severity ladder.
- **Recommended fix**: Remove `password` before logging, for example `log.info("request %s", {k: v for k, v in body.items() if k != "password"})`. Better still, change the `CLAUDE.md` rule so handlers log a redacted body, with sensitive keys like `password`, `token`, and `secret` masked. Otherwise every future handler that follows the rule will leak the same way.

### Finding #2: A missing `username` or `password` field raises an unhandled `KeyError`
- **Location**: `login.py:5-6`
- **Type**: Edge Cases / Error Handling
- **Severity**: Medium
- **Description**: The handler reads `body["username"]` and `body["password"]` directly. If either key is missing, it raises `KeyError` instead of returning a failed login. If `body` is `None`, it raises `TypeError`, after line 4 has already logged it.
- **Trigger**: A request body without one of the keys, such as `{"username": "admin"}`. Line 6 raises `KeyError: 'password'`.
- **Impact**: Malformed login requests come back as an unhandled exception (a 500 or a crashed handler, depending on the framework), not `{"ok": False}` or a 400.
- **Recommended fix**: Validate the input, for example `user = body.get("username"); password = body.get("password")`, and return `{"ok": False}` or a 400 when either one is missing.
