**The problem:** agents run the same ticket searches all day and type in every filter each time. Getting one wrong means rerunning the search.

**The plan, in your three deliverables:**

The database rejects two saved searches with the same name for one agent, and deleting an agent's account deletes their saved searches. The migration only adds a new table and can be rolled back.
2. **Endpoints (create, list, delete):** they only ever see the logged-in agent's own saved searches. Asking for another agent's search returns 404, the same as a search that doesn't exist. Error messages are written so the UI can show them as they are.
3. **Sidebar:** a "Save search" action on the search view and a "Saved searches" list in the sidebar. Clicking an entry applies its filters, so results are always current. Each entry can be deleted after a confirmation. The spec also covers the empty, loading, error and full-at-50 states.

- Saved searches are private, and there's no sharing.
