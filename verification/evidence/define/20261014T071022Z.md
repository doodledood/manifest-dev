**The problem:** agents run the same ticket searches all day and have to retype every filter each time. That's slow, and a mistyped filter quietly returns the wrong tickets.

**I changed how the three deliverables are split.** I kept the scope and the count of three, but each one now works end to end on its own instead of being one layer:
1. **Save a search and run it from the sidebar.** This covers the model, the migration, the create and list endpoints, a "Save search" button and the sidebar list. It's done when an agent saves "open / high / billing", clears the filters, clicks the saved entry and gets the same tickets back. It also has to pick up a ticket created after the save, so it stores the filters rather than the results.
2. **Delete from the sidebar.** This covers the delete endpoint and a delete button with a confirm step. Only the chosen search goes away, and it stays gone after a reload.
3. **Hitting the 50 limit.** Trying to save a 51st search gets a clear message. Deleting one and saving again then works.

If you want it split by layer as you asked, say so and I'll switch it back; nothing else changes.

**Rules that must hold:**
- **Privacy:** an agent only ever sees and deletes their own searches. Asking for someone else's returns "not found", the same as a search that doesn't exist. The owner is always taken from who's logged in, never from the request.
- **No sharing and no editing:** there's no shared or team flag and no Django admin listing. Edit requests are rejected, and there's no rename button.
- **The 50 cap:** it's enforced on the server, and two saves at the same moment can't push an agent past it.
- **Migration:** it only adds the new table and can be fully rolled back.
- **Failures:** every failure shows the agent a readable message, never a raw error.
- **Checks:** your existing test, lint and type checks must pass, and there's a visual review of the sidebar and a full code review.

**Choices I made myself, since you weren't around (all easy to change):**
- Names are required, up to 100 characters, and no agent can have two with the same name, ignoring case. Different agents can reuse a name.
- The sidebar is sorted alphabetically.
- Deleting asks for confirmation first.
- The search is stored in whatever format your ticket search already uses for its filters. This is the riskiest guess: if the filters only live inside the page's own state, the search screen needs a small refactor first.
- Nothing covers getting the change through a pull request, CI or review.
