## What it should be

- **New `src/reminders.py`** with one pure function, e.g. `reminder_messages(overdue) -> [(member, subject, body)]`. It groups overdue loans by member and gives one message per member, listing every overdue book with its days overdue. It does no file or network I/O.
- **New `remind` branch in `src/shelfnote.py:13`**, next to `overdue`. It loads the loans, calls `overdue_loans()`, calls `reminder_messages()`, then calls `mailer.send_to_member()` once for each message.
- **Output:** one tab-separated line per member (`sent`, `skipped (no address)` or `failed`) and a total. This matches the style of `overdue` (`shelfnote.py:15`).
- **Tests:** pass a fixed `today` to `overdue_loans()`, as the existing test does (`tests/test_loans.py:10`), and test `reminder_messages()` directly. Replace `send_to_member` with a fake to test the skip and failure paths. Tests never open a real email connection.

## Evidence
- `get_overdue()` would repeat `loans.overdue_loans()` (`src/loans.py:11-21`). That function already drops returned loans, adds `days_overdue` and sorts oldest first.
- `send()` would repeat `mailer.send_to_member()` (`src/mailer.py:9-19`). The module says *"Every message the tool sends goes through here"* (`mailer.py:1`). A second send path would break that rule.
- In a throwaway copy, I gave one member two overdue loans. `overdue_loans()` returned `[('ana','A',24),('cleo','C',24),('ana','B',20)]`. The member's loans are mixed in with other members' loans, so sending per loan would email ana twice. Grouping by member is real work, and it belongs in the compose step.
- `send_to_member('cleo', …)` returned `False` and sent nothing. A member with no address on file is skipped silently today, so the command must report it.
