# ADR: Positioning drops the conversion funnel; the standalone shape stays on honest grounds

## Status
Accepted

## Area
Positioning

## Context
Four North Star fields described a project pursuing adopters. `How they arrive` named discovery
channels and a front door built so a newcomer feels value before adopting the method. `What this
rests on` carried an assumption that a single standalone skill, met first, converts a newcomer
into a user of the full loop. `Open` asked whether that front door actually converts. And the
`Promise` was written as the sentence that would hook a stranger, at the single-task unit the
Diagnosis had already moved away from.

None of that matched the practice. No channel was being worked and no funnel maintained; the
owner's position is that the project is built in public and owned, with outside help not wanted
and outside use welcome but not pursued. The Winning ruling of the same day had already recorded
recognition as a consequence rather than a target. So the fields were not merely unmeasured —
they stated an intent that was not held, which is the failure the surface exists to prevent.

The Promise raised a second question: whether moving it to the project unit meant dropping the
task-level claim. It does not. Trustworthy output is what a user feels first, and an agent can
still be exactly right about the wrong work — the two halves are causally joined rather than
stacked, the second being the condition that makes the first worth anything. That reading is the
Diagnosis's own: the agent's speed multiplies work nobody can tell was worth doing.

## Decision
Arrival is not pursued. `How they arrive` states that the project is built in public and shared
as it is used, with no channel worked and no funnel maintained, and that whatever someone meets
first stands alone so nothing must be adopted whole.

The Promise carries both units. It keeps the existing task-level bar verbatim inside a wider one
that adds coming back to a project which still knows what it is becoming, what is next, and what
done means.

The conversion assumption is deleted from `What this rests on` rather than reworded: the project
no longer rests on it.

`Open` retires the front-door conversion question and asks instead whether the project-level half
of the promise holds for anyone but its author, to be filled by someone who is not the maintainer
keeping a project's direction, queue, and definition of done in these surfaces.

The standalone-first shape is kept. Its justification changes from conversion to honesty: meeting
one skill first is the true entry to the method, whatever it does for adoption.

## Alternatives Considered
- **Move the Promise wholly to the project unit**: Rejected by the owner — the task-level trust
  claim is still a large part of what the project is for, and dropping it would understate what a
  user actually feels.
- **Leave the Promise at the task unit and change nothing else**: Rejected — it would leave the
  documentation faithfully describing one of three tiers, which is what made the README read as
  stale in the first place.
- **Declare a contributions-not-wanted policy on the repository's surfaces**: Rejected by the
  owner — a stated prohibition is itself a closed door, and the aim is not to close one.
- **Reword the conversion assumption rather than delete it**: Rejected — an assumption is what the
  project rests on, and this one no longer bears any weight; a softened version would still be
  read as a live commitment.
- **Retire the standalone-first shape along with its conversion rationale**: Rejected — the shape
  is independently correct, since the method genuinely begins with understanding, and only its
  justification was funnel-shaped.

## Consequences

### Positive
- The document states an intent that is actually held, so future scoping is checked against
  something real.
- The documentation rewrite becomes an addition rather than a replacement: the task-level material
  stays true and what is missing is the tier above it.
- `Open` now holds a question that could actually be answered by something the project would
  notice, rather than one about a funnel nobody is running.

### Negative
- The project keeps no stated account of how anyone finds it, so if arrival ever matters again
  that thinking starts from nothing.
- A two-part promise is harder to land in one line than a single-pain accusation, and the wider
  bar is the less immediately felt of the two halves.
- Deleting the conversion assumption removes the only line that recorded why the standalone shape
  was chosen; this record carries that history instead.
