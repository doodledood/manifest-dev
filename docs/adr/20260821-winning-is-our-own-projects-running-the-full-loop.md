# ADR: Winning is our own projects running the full loop; recognition is a consequence

## Status
Accepted

## Area
Positioning

## Context
The North Star's `Winning, and the number watched` field stood `empty` since the document was
created, carrying its own filling condition: the owner deciding whether winning is external
adoption or the workflows serving our own projects end-to-end, and then naming the one count
that tracks it. An empty Winning field leaves every scoping and priority call without a
destination to be checked against — `next-ticket`'s cross-effort comparison in particular has
no measure to appeal to, since impact is only defined within an effort.

Two candidates were on the table, in the order the field requires: the destination first, the
count second. A count proposed ahead of the destination — a public popularity number — would
have named the instrument before the goal, and would have set the project watching a figure
whose fastest lever is the promotional register a standing Never forbids. The conventions also
bar live readings from the document, so whatever is named must be a shape, not a value.

The choice was not open in both directions to the same degree. The `Money — or what it feeds`
position already rules that these workflows are built for our own projects first and that
distribution stays secondary to getting the workflows right; it has stood since the first
strategy doc. A winning definition resting on external adoption would have contradicted a
standing ruling without that ruling being moved.

The unit the definition ranges over comes from the rewritten Diagnosis: three contracts at
three lifetimes, each making the tier below it decidable. "End-to-end" therefore means all
three tiers carrying real work, not the execution tier alone.

## Decision
Winning is our own projects running end-to-end on all three tiers — a North Star that stands,
work pulled from a Ticket store rather than from whoever is at the keyboard, and execution
against a Manifest with gate evidence. Outside recognition is welcome as a consequence of that
working; it is never a target traded against it.

The number watched is how many of our own projects are running all three tiers at once. It is
named as a shape, and the document carries no reading of it, per the conventions' rule that
live metric readings stay out.

## Alternatives Considered
- **Winning is external adoption**: Rejected — it contradicts the standing `Money` ruling that
  distribution stays secondary, and that ruling was not moved.
- **A public popularity count as the watched number**: Rejected on two grounds — it names a
  count while the destination above it is unchosen, inverting the field's own filling order;
  and its fastest lever is the register the Nevers forbid, so the project would be watching a
  number that rewards what it refuses to do.
- **A clone or install count as the watched number**: Rejected as the primary number for the
  same reason as adoption — it measures arrival, not whether the workflows carry our own work.
  It remains available as a secondary signal if the owner later wants one, and naming it would
  not collide with the Nevers, which bar readings and commentary rather than instruments.
- **Ruling that this project carries no number** (explicitly permitted by the conventions):
  Rejected — the destination is countable as stated, and a destination with no number is
  unwatchable, which is the failure mode the paired field exists to prevent.
- **An execution-tier count** (runs completed, gates passed, escalations avoided): Rejected —
  it measures the Manifest tier, which is the unit the Diagnosis was rewritten away from, and
  would read healthy while the project drifted.

## Consequences

### Positive
- Scoping and priority calls gain a destination to be checked against, including cross-effort
  comparison, which had no measure before.
- The number reads near-zero at the time of this decision and can only move by the workflows
  actually carrying our own work, so it cannot be satisfied by promotion or by activity.
- It makes an unused tier visible rather than arguable: a project without a Ticket store does
  not count, whatever else it runs.

### Negative
- The number ranges over a small set, so it moves in large steps and will not give fine-grained
  feedback.
- It says nothing about whether anyone outside is served, by construction — a deliberate
  consequence of the ruling, and one that leaves the door question in `Open` unanswered.
- Adopting a tier in order to move the number is a live failure mode; the number counts tiers
  carrying real work, and a store created to be counted would be the thing it is meant to catch.
