# ADR: Shipped skill text is host-neutral; distributions read the source tree instead of rewriting it

## Status
Accepted

## Area
Repo layout

## Context
Every skill under `claude-plugins/` was written for Claude Code and rewritten per host by `/sync-tools`: a 535-line prompt with three per-CLI references that a model ran to produce `dist/codex`, `dist/opencode`, and `dist/pi`, tracked through `.sync-meta.json` files and a Pi `component-namespaces.json`. Measuring the transform against the shipped tree showed it was almost entirely three mechanical substitutions — the `manifest-dev:`/`manifest-dev-tools:` plugin qualifier stripped from skill references, `CLAUDE.md` renamed to the host's context file, and a handful of Claude Code tool names reworded — spread across 116 files. The remaining host-specific wording, "subagent", was never rewritten by any distribution, so hosts without a subagent primitive were handed prose that could not be followed.

Two further defects sat beside the transform. `metadata: internal: true`, introduced by `20260705-keep-plugin-first-layout-npx-skills-compatible` for repo-maintenance skills, had been applied to `done`, `escalate`, and `poll-slack`, which are runtime dependencies of the ticket workflows; the cross-agent skill picker skips internal skills, so a user who installed `run-ticket` through it got a skill whose completion path named a skill that did not ship. And `review-pr` carried three delegated briefs — per-thread verification, the holistic pass, and the judgment pass — inline or in a reference, addressed to a subagent, so on hosts without that primitive the briefs had no execution path at all.

The constraint from `20260705` stands: existing plugin users must see no path change, and the layout under `claude-plugins/` and `dist/` is not restructured.

## Decision
Make the source text the shipped text on every host, and hold that with two invariants enforced by tests over the whole tree of shipped Markdown:

1. **No shipped file names a host primitive.** No plugin qualifier outside an HTML comment, no Claude Code tool name, `CLAUDE.md` only where a file also names `AGENTS.md` (a detection or comparison) or sits under a `references/research/` digest, and no "subagent" outside such a digest. Delegated work is phrased as launching an isolated execution context that activates a named skill, and every such site carries an inline fallback for hosts that have none — the `/do` verification modes being the deliberate exception, which stop and report rather than silently downgrade their provenance.
2. **Every skill a shipped skill names ships beside it, and loads on every host.** No shipped skill carries `metadata.internal`; a skill that exists only to be invoked by another (`done`, `escalate`, `poll-slack`, and the three briefs extracted from `review-pr` as `review-pr-thread-verify`, `review-pr-holistic`, `review-pr-judgment`) is `user-invocable: false`, which every host either honors or ignores, and the picker installs.

With the text host-neutral, the distributions stop carrying copies: the OpenCode plugin registers the two source skill directories as skill paths, and the Pi package manifest points `pi.skills` at the same two directories; `dist/opencode/skills`, `dist/pi/skills`, the Pi namespace file, and the `.sync-meta.json` files are deleted. Codex installs from a plugin cache and needs files under the plugin directory, so `dist/codex/plugins/*/skills` remains as a byte-identical copy regenerated by `scripts/sync_dist.py` and checked for drift by the test suite. `/sync-tools` is reduced to a wrapper that runs the script and lists the hand-maintained packaging files.

## Alternatives Considered
- **Hoist a canonical root `skills/` directory and demote the Claude Code plugin to `dist/`**: the layout the skill-picker ecosystem converges on — Rejected again, on the grounds `20260705` gave: the layout was never what blocked installability, the transform was, and a restructure would break the paths existing plugin users have installed.
- **Delete `dist/` entirely and install every host from source**: the simplest tree — Rejected because Codex installs from a private plugin cache populated from the plugin directory, so a copy under `dist/codex` has to exist; a scripted byte-identical copy with a drift test costs nothing to maintain.
- **Keep the model-run `/sync-tools` and fix the `internal` marker only**: the smallest change — Rejected because the transform was the maintenance cost, its rules had already drifted (the subagent wording was never rewritten), and a model-run rewrite is exactly the surface a test cannot prove authorized.
- **Mark dependency-only skills with `disable-model-invocation` instead of `user-invocable: false`**: the field Pi honors — Rejected because it means the inverse: it makes a skill user-only, and these skills must be invocable by the model and hidden from the slash menu. Claude Code and OpenCode read `user-invocable`, and Pi and Codex ignore unknown fields, so the marker is safe everywhere.

## Consequences

### Positive
- One text per skill on every host, so a fix lands once and a test proves the shipped tree still carries no host primitive.
- Installing any skill through the cross-agent picker yields a skill whose every named dependency ships with it.
- `dist/` is a packaging concern only: OpenCode and Pi need no regeneration step, and Codex regenerates by one script whose output a test checks.
- `/sync-tools` shrinks from a 535-line prompt plus three references to a wrapper around the script.

### Negative
- Prose that once named a tool exactly now names the capability, which is a shade less specific on the host that had the tool.
- A host that gains a primitive worth naming gets it only through capability language, never a per-host rewrite.
- `dist/codex` still duplicates the source tree in git, so the drift test is what keeps it honest.

## Enforced by
`tests/test_skill_frontmatter.py` — `test_shipped_text_names_no_plugin_qualifier_outside_html_comments` and `test_shipped_text_names_no_host_tool`; `tests/test_dist_skill_references.py` — `test_opencode_reads_the_source_skill_directories`. Also `tests/test_dist_install_uninstall.py` — `test_opencode_ships_no_installer_artifacts`, `test_opencode_registers_every_source_skill_root`; `tests/test_dist_skill_references.py` — `test_sync_tools_is_a_wrapper_around_the_copy_script`, `test_pi_package_metadata_points_to_source_skills_and_prompts`, `test_pi_dist_carries_only_prompt_aliases`; `tests/test_skill_frontmatter.py` — `test_shipped_text_names_the_context_file_only_where_it_detects_or_compares`, `test_shipped_text_never_names_a_subagent_outside_research_digests`, `test_every_delegation_site_carries_an_inline_fallback`, `test_no_shipped_skill_is_marked_internal`, `test_every_skill_a_shipped_skill_names_ships_beside_it`, `test_every_dependency_only_skill_is_not_user_invocable` fail if OpenCode or Pi stops reading the source skill directories, sync-tools stops wrapping the copy script, or shipped text names the context file outside a detection or comparison, names a subagent outside a research digest, delegates without an inline fallback, marks a skill internal, names a skill that does not ship beside it, or leaves a dependency-only skill user-invocable.
